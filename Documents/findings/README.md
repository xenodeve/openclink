# Findings dataset — the raw material behind the report and the blueprint

`claims.jsonl` คือ **605 ข้ออ้างดิบ** จากการสแกน codebase สามรอบเมื่อ 2026-08-13 ที่ `2aa6e49` · หนึ่งบรรทัดหนึ่งข้ออ้าง พร้อม `file:line` เป็นหลักฐาน

**เหตุผลที่ไฟล์นี้มีอยู่** — [รายงาน](../../docs/reports/2026-08-13-deep-scan-architecture-safety-and-direction.md) กับ [พิมพ์เขียว](../DOCUMENT_INDEX.md) กลั่นออกมาราว 150 ข้อ ที่เหลืออีกราว 450 ข้อไม่ได้หายไปเพราะผิด แต่เพราะไม่ได้เปลี่ยนลำดับความสำคัญ · **ถ้าวันหน้ามีคำถามที่เอกสารสองฉบับนั้นไม่ตอบ ให้ grep ไฟล์นี้ก่อนสั่งสแกนใหม่** เพราะการสแกนสามรอบใช้ไปแล้วราว 7.5 ล้าน token

## รูปร่างของแต่ละบรรทัด

```json
{
  "round": "round1 | round2 | round3",
  "area": "ระบบย่อยที่ reader ตัวนั้นรับผิดชอบ",
  "id": "slug สั้น ไม่ซ้ำภายใน area",
  "kind": "defect | risk | gap | constraint | architecture | capability | opportunity",
  "register": "verified | inferred | unknown",
  "statement": "หนึ่งประโยค เจาะจง พิสูจน์ผิดได้",
  "evidence": ["file:line ...", "หรือคำสั่งกับผลลัพธ์"],
  "why": "ผลต่อการพัฒนา PAL ต่อไป",
  "search_boundary": "สำหรับข้ออ้างเชิงลบ — ค้นอะไรไป และค้นนั้นเอื้อมไม่ถึงอะไร",
  "refutation": { "refuted": true, "reason": "...", "corrected_statement": "..." }
}
```

|---|---|
| ข้ออ้างทั้งหมด | **605** |
| แยกตามรอบ | round1 223 · round2 157 · round3 225 |
| แยกตามชนิด | defect 224 · gap 66 · constraint 55 · architecture 54 · risk 51 · opportunity 30 · capability 19 |

## วิธีอ่านให้ถูก — สามข้อ

**หนึ่ง `register: "verified"` แปลว่า reader อ้างว่าตัวเองอ่านหรือรันมา ไม่ได้แปลว่าใครไปตรวจซ้ำ** · จาก 605 ข้อ มี 27 ข้อที่ถูก agent อิสระพยายามหักล้าง และ **11 ในนั้นไม่รอด** — อัตราหักล้าง **41%**

**สอง ให้ระวังคำที่เป็นสัมบูรณ์เป็นพิเศษ** — "ไม่มีเลย" "ไม่เคย" "อันเดียว" "ทั้งหมด" · ข้อที่ถูกหักล้างทั้ง 11 ข้อเป็นข้ออ้างเชิงลบหรือเชิงสัมบูรณ์ ส่วนข้ออ้างเชิงบวกรอดแทบทั้งหมด · **งบการตรวจสอบรอบหน้าควรลงที่คำพวกนี้**

**สาม ข้อที่ผ่านเข้าไปอยู่ในรายงานหรือพิมพ์เขียวแล้ว ถูกตรวจซ้ำด้วยมือ** ส่วนข้อที่ยังอยู่แต่ในไฟล์นี้ไม่ได้ถูกตรวจ · อย่าลงมือแก้อะไรจากบรรทัดในไฟล์นี้โดยไม่ยืนยันด้วยตัวเองก่อน — ค่าใช้จ่ายในการยืนยันหนึ่งข้อคือ `grep` หนึ่งครั้ง ซึ่งถูกกว่าการแก้ผิดมาก

## ตัวอย่างการใช้

```sh
# ข้อบกพร่องทั้งหมดในชั้น provider
grep '"round"' claims.jsonl | grep -i 'provider' | grep '"kind": "defect"'

# ทุกข้อที่แตะไฟล์หนึ่ง
grep 'tools/clink.py' claims.jsonl

# ข้อที่ถูกหักล้าง — อ่านก่อนอ้างข้ออ้างเชิงลบข้อไหนก็ตาม
grep '"refuted": true' claims.jsonl
```

## ที่มา

สามรอบ ไม่เหมือนกันโดยตั้งใจ · **รอบ 1–2** ใช้ผู้อ่านสิบสองตัวแล้วส่งข้ออ้างที่แบกน้ำหนักให้ agent อีกตัวพยายามทุบ — 80 agent ราว 6 ล้าน token และการหักล้าง 41 จาก 68 ครั้งไม่ได้รันเพราะโควตาหมด · **รอบ 3** ตัดชั้นหักล้างทิ้ง ใช้ผู้อ่านแปดตัวแล้วให้ผู้สังเคราะห์ตรวจข้อที่ระบุชื่อเองในลูปหลัก — 1.51 ล้าน token ไม่มีตัวไหนตาย

**ผลเชิงวิธีการที่ควรใช้ต่อ** — รอบ 3 ถูกกว่าราวสี่เท่าต่อข้ออ้าง และการตรวจแบบเจาะจงโดยผู้สังเคราะห์ให้ตัวเลขที่คมที่สุดในรายงานทั้งฉบับ (การนับ newline ด้วย `ast` · การทดสอบ path บน Windows · การพิสูจน์ว่า allowlist เปลี่ยนเส้นทางแทนที่จะปฏิเสธ) · **การตรวจเจาะจงชนะการกระจายตัวหักล้างทั้งเรื่องราคาและความแม่น**
